With plain HTML, each page is a file: `about.html` is the about page. Next.js keeps that simple idea and moves it into folders.

**A folder inside `app/` is a piece of the URL. A file named `page.js` inside it is what people see there.**

<Flow
  label="The file app/about/page.js becomes the URL /about"
  steps={['app/about/page.js', 'yoursite.com/about']}
  actions={['becomes']}
/>

| File | URL |
| --- | --- |
| `app/page.js` | `/` |
| `app/about/page.js` | `/about` |
| `app/projects/page.js` | `/projects` |
| `app/projects/game/page.js` | `/projects/game` |

This is called **file-based routing**. A **route** is just a URL your site responds to. There's no list of pages to keep up to date anywhere. If the folder and the file exist, so does the page.

## What goes in a page

A page is a React component in a file called `page.js`, exported with `export default`:

```jsx title="app/about/page.js"
export default function AboutPage() {
  return (
    <section className="page">
      <h1>About me</h1>
      <p>I joined MISA to build things people actually use.</p>
    </section>
  );
}
```

The function can have any name. The file can't. It has to be exactly `page.js`, in lowercase.

## You'll see square brackets

Sometimes a site has hundreds of pages with the same shape, like one per product. Nobody makes hundreds of folders. They make one, with square brackets in its name:

```text
app/projects/[slug]/page.js
```

That single file handles `/projects/game`, `/projects/flashcards`, and any other word in that spot. This is a **dynamic route**. You don't need to write one yet. It's enough to recognize the brackets and know what they're for.
