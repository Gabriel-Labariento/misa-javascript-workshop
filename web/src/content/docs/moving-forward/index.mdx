You finished a game, which means you already know enough JavaScript to make decisions, repeat work, organize data, react to the mouse and keyboard, and split a program into modules and classes. Pick something you want your next program to do, then learn the part of JavaScript that helps you build it.

These lessons continue from the workshop for independent practice. Follow them in order or jump to the one your next idea needs.

## Choose a route

| If you want to... | Start here |
| --- | --- |
| Search, filter, transform, or sort a list of values | [More with arrays](./arrays/) |
| Clean names, split sentences, or format prices | [Work with text](./text/) |
| Stop listening, listen once, or send your own events | [Events in depth](./events/) |
| Make the game work with touch screens and pens | [Mouse, touch, and pen](./pointer-events/) |
| Create a more specific version of an existing class | [Reuse with inheritance](./inheritance/) |
| Keep a high score after the page closes | [Remember a high score](./storage/) |
| Give your game a link anyone can play | [Put your game online](./publishing/) |

Inheritance makes more sense after you're comfortable with classes. The other lessons can be taken in any order.

## How to use each lesson

Every lesson has examples you can run on the page. Predict what each will do, run it, then change one value and run it again. Reading code can make an idea feel familiar; changing it shows whether you understand it.

When a lesson gives you a practice task, try it before opening a larger project. Each task should take ten to twenty minutes, and it's fine if your version looks different from someone else's.

When you're ready to make something of your own, [pick a project](../projects/). Each project starts with an empty folder and grows through working milestones. The pages describe what the program should do without deciding every name, message, or feature for you.

## Keep one habit from the workshop

Check the page after every small change. If it stops working, the cause is probably in the few lines you just touched, and the console's first red line usually points right at it. Save a Git commit whenever a useful milestone works, so you can experiment without losing that version.

[MDN's JavaScript Guide](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide) is the reference most web developers use. Look up one topic at a time. [javascript.info](https://javascript.info/) is a free, beginner-friendly tutorial if you want a second explanation of any idea.
