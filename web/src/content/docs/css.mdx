## What CSS does

CSS is a list of **rules**. Each rule picks some elements and says how they should look:

```text title="One rule"
h2 {               ← selector: which elements
  color: #087a80;  ← declaration: property: value;
}
```

Each line inside the braces is a **declaration**: a **property** (what to change), a colon, a **value** (what to change it to), and a semicolon. A rule can hold as many declarations as you like. Here are the first two rules for the card:

<Playground height={380}>
```css
body {
  color: #102a2c;
  font-family: system-ui, -apple-system, "Segoe UI", Roboto, sans-serif;
  background: #f3fbfb;
}

h2 {
  color: #087a80;
}
```
```html
<article class="card">
  <img class="card-photo" src="assets/misabot.png" alt="MISAbot smiling" width="96" />
  <div class="card-body">
    <h2>Niles Cabrera</h2>
    <p class="card-role">BS MIS · Lead developer</p>
    <p>I build small web tools and never say no to turon.</p>
    <ul class="card-tags">
      <li>HTML</li>
      <li>CSS</li>
      <li>React</li>
    </ul>
    <a class="card-link" href="https://github.com/">My GitHub</a>
  </div>
</article>
```
</Playground>

`#087a80` is a color written as a **hex code**: two digits each for red, green, and blue. Color names work too.

Some properties, like `color` and `font-family`, are **inherited**: children take them from their parent unless a rule says otherwise. Try it: change the color in `body` to `tomato` and press **▶ Run** again. Every paragraph turns red, although no rule names them. The heading stays teal, because its own rule wins.

In a real project, the CSS lives in its own file, and the HTML page loads it from the `<head>`:

```html title="index.html (inside <head>)"
<link rel="stylesheet" href="style.css" />
```

## Pick what to style

The part before `{` is the **selector**. These four cover most of what you'll write:

| Selector | Picks | Example |
| --- | --- | --- |
| `h2` | every `<h2>` | `h2 { color: #087a80; }` |
| `.card-role` | every element with `class="card-role"` | the dot means "class" |
| `#greeting` | the one element with `id="greeting"` | the `#` means "id" |
| `.card h2` | every `<h2>` inside a `.card` | a space means "inside" |

## Every element is a box

The browser draws every element as a rectangle with four layers, from the inside out. This is the **box model**:

```text title="The box model"
┌──────────────── margin ────────────────┐
│ ┌───────────── border ───────────────┐ │
│ │ ┌────────── padding ─────────────┐ │ │
│ │ │            content             │ │ │
│ │ └────────────────────────────────┘ │ │
│ └────────────────────────────────────┘ │
└────────────────────────────────────────┘
```

- **content** is the text or image itself.
- **padding** is space inside the border, between it and the content.
- **border** is the line around the element.
- **margin** is space outside the border, pushing other elements away.

<Playground height={420}>
```css
* {
  box-sizing: border-box;
}

body {
  color: #102a2c;
  font-family: system-ui, -apple-system, "Segoe UI", Roboto, sans-serif;
  background: #f3fbfb;
}

p {
  margin: 0 0 0.75rem;
}

.card {
  max-width: 32rem;
  padding: 1.25rem;
  background: white;
  border: 2px solid #b9dcdc;
  border-radius: 1rem;
}

.card-photo {
  width: 6rem;
  height: 6rem;
  padding: 0.5rem;
  object-fit: contain;
  background: #e3f6f6;
  border-radius: 50%;
}

.card h2 {
  margin: 0;
  color: #087a80;
  font-size: 1.4rem;
}

.card-role {
  margin-bottom: 0.5rem;
  color: #4a6668;
  font-size: 0.9rem;
  font-weight: 600;
}

.card-link {
  color: #087a80;
  font-weight: 700;
}
```
```html
<article class="card">

  <div class="card-body">

      <li>HTML</li>
      <li>CSS</li>
      <li>React</li>
```

`rem` is a size based on the page's text size, so `1rem` is usually 16px and `1.25rem` is 20px.

`*` selects every element. `box-sizing: border-box` makes `width` include the padding and border, so a box you set to `6rem` stays `6rem`. Almost every project starts with this rule.

`border-radius` rounds the corners, and `50%` turns a square into a circle.

You can see any element's box in the browser. Right-click it, choose **Inspect**, and look for the box diagram in the **Styles** or **Computed** panel. Hover over its layers to highlight them on the page.

<Predict question="How wide is this box on the page?" options={['200px', '220px', '240px']} answer={2}>
```css
.box { width: 200px; padding: 20px; }
```

Without `box-sizing: border-box`, padding is added on both sides: 200 + 20 + 20 = 240px. With `border-box`, the box stays 200px wide and the content shrinks instead.

## Line things up with flexbox

The photo sits above the text, because the browser stacks blocks from top to bottom. **Flexbox** puts children in a row instead. Add `display: flex` to the parent. From here on, each example's new rules sit at the top of its CSS tab:

<Playground height={320}>
```css
/* New: flexbox */
.card {
  display: flex;
  gap: 1.25rem;
  align-items: center;
  max-width: 32rem;
  padding: 1.25rem;
  background: white;
  border: 2px solid #b9dcdc;
  border-radius: 1rem;
}

.card-photo {
  flex-shrink: 0;
  width: 6rem;
  height: 6rem;
  padding: 0.5rem;
  object-fit: contain;
  background: #e3f6f6;
  border-radius: 50%;
}

.card-tags {
  display: flex;
  flex-wrap: wrap;
  gap: 0.4rem;
  margin: 0 0 0.75rem;
  padding: 0;
  list-style: none;
}

/* New: each tag as a pill */
.card-tags li {
  padding: 0.15rem 0.65rem;
  color: #087a80;
  font-size: 0.8rem;
  font-weight: 700;
  background: #e3f6f6;
  border-radius: 999px;
}

/* From the last step */
* {
  box-sizing: border-box;
}

body {
  color: #102a2c;

  background: #f3fbfb;
}

  margin: 0 0 0.75rem;
}

.card h2 {
  margin: 0;
  color: #087a80;
  font-size: 1.4rem;
}

.card-role {
  margin-bottom: 0.5rem;
  color: #4a6668;
  font-size: 0.9rem;
  font-weight: 600;
}

.card-link {
  color: #087a80;
  font-weight: 700;
}
```
```html
<article class="card">
  <img class="card-photo" src="assets/misabot.png" alt="MISAbot smiling" width="96" />
  <div class="card-body">
    <h2>Niles Cabrera</h2>
    <p class="card-role">BS MIS · Lead developer</p>
    <p>I build small web tools and never say no to turon.</p>
    <ul class="card-tags">
      <li>HTML</li>
      <li>CSS</li>
      <li>React</li>
    </ul>
    <a class="card-link" href="https://github.com/">My GitHub</a>
  </div>
</article>
```
</Playground>

Flexbox is used twice here: once on `.card` for photo and text, and once on `.card-tags` for the list items.

- `display: flex` lines up the element's children in a row.
- `gap` puts space between them.
- `align-items` lines them up across the row: `center`, `start`, or `end`.
- `justify-content` spreads them along the row: try `center` or `space-between` on `.card-tags`.
- `flex-direction: column` stacks them instead. You'll use it in the next example.
- `flex-shrink: 0` stops the photo from getting squeezed when space runs out.

## Lay out rows and columns with grid

Flexbox handles one direction at a time. **Grid** handles rows and columns together, which suits a set of cards. Like flexbox, grid goes on the parent, so this example changes the HTML: three cards now sit inside a `<section class="cards">`. Its CSS starts with the new rules:

- `display: grid` on `.cards` turns its children into grid items.
- `grid-template-columns` sets the columns. `repeat(auto-fit, minmax(12rem, 1fr))` means "fit as many columns as you can, each at least `12rem` wide, sharing leftover space equally". On a narrow screen, the cards drop to fewer columns on their own.
- `1fr` is one **fraction** of the free space. `grid-template-columns: 1fr 1fr 1fr` would always make three equal columns.
- Inside each card, `flex-direction: column` stacks the photo above the text again.

Which one should you use? Flexbox for a single row or column of things; grid when you're arranging rows and columns at once. Most layouts use both.

<details>
<summary>Read later: units, colors, and the cascade</summary>

**Units.** `px` is a fixed size. `rem` is relative to the page's base font size (usually 16px), so `1.25rem` is 20px and everything grows together if a reader enlarges their text. `%` is relative to the parent. Prefer `rem` for spacing and text.

**CSS variables.** Repeating `#087a80` everywhere gets tiring. Name a value once and reuse it with `var()`. The game's stylesheet in the JavaScript lessons starts this way:

```css
:root {
  --teal: #19aab1;
  --teal-dark: #087a80;
}

.card h2 {
  color: var(--teal-dark);
}
```

**The cascade.** When two rules set the same property on the same element, the more specific selector wins: an id beats a class, and a class beats an element name. If they're equally specific, the rule that comes later wins.

```css
p { color: black; }
.card-role { color: gray; }  /* wins for the role line: a class beats an element */
```

**Phones.** A **media query** applies rules only when a condition is true, like a narrow screen:

```css
@media (max-width: 40rem) {
  .card {
    flex-direction: column;
    text-align: center;
  }
}
```

</details>

## From CSS to React

CSS works the same in React and Next.js. Two things change:

- You attach classes with `className="card"` instead of `class="card"`, as the [HTML page](../html/#from-html-to-react) showed.
- Next.js loads styles a little differently. A global stylesheet such as `app/globals.css` is imported once and applies everywhere. A **CSS module** such as `Card.module.css` applies only to the component that imports it, so class names never clash.

Tailwind, a popular way to style with ready-made class names, gets its own module.
